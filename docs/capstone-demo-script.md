# Eureka Flow — 캡스톤 부스 시연 대본

_혼자 말하면서 화면을 조작하는 연속 대본. [화면]은 동작 지시. 실제 생성은 몇 분 걸리고 비용이 들어서, 라이브는 "워크플로우가 자동으로 구성되고 실행되는 것"까지 보여주고 완성 영상은 미리 렌더해둔 걸 재생한다._

---

안녕하세요. 저희가 만든 건 **Eureka Flow**, 한마디로 **자동화 워크플로우 플랫폼**입니다.

이런 도구들 보면 보통 블록, 그러니까 노드를 사람이 하나하나 직접 연결해서 자동화를 짜야 하거든요. 저희는 거기서 한 발 더 나갔어요. **사람이 워크플로우를 안 짭니다. 말로 시키면 AI가 알아서 짜요.**

[화면] 빈 캔버스를 보여준다.

지금 화면은 비어 있죠. 제가 그냥 말로 시켜볼게요.

[화면] 채팅창에 입력: **"AI 반도체 트렌드로 쇼츠 하나 만들어줘"**

이렇게 자연어로 넣으면, 먼저 **오케스트레이터 AI가 이 요청을 판단합니다.** 그냥 잡담인지, 뭔가 만들어 달라는 요청인지를 구분하고요. 만들어 달라는 거면, 이게 쇼츠 영상 요청인지 글인지 이미지인지를 파악해요. 그리고 그에 맞춰서 **어떤 블록들로 워크플로우를 구성할지** 결정합니다.

[화면] 잠시 후 캔버스에 노드들이 좌라락 깔린다. 노드들을 손으로 짚으며.

보세요, 방금 이게 깔렸죠. **자료 수집 → 대본 작성 → 장면 구성 → 이미지 생성 → 음성 더빙 → 영상 합성 → 메타데이터.** 쇼츠 한 편을 만드는 데 필요한 단계들이 순서대로 연결돼 있어요. 중요한 건, **이 구성을 제가 미리 짜둔 게 아니라는 거예요.** 방금 제 요청 한 줄을 보고 AI가 자동으로 만든 겁니다.

이대로 승인하고 실행하면, 각 노드가 순서대로 돌아갑니다.

[화면] 승인·실행 클릭. 노드들이 하나씩 초록불로 바뀐다. 10~15초 보여주며.

지금 실시간으로 각 단계가 돌고 있는 거예요. 자료를 찾고, 대본을 쓰고, 장면을 나누고, 이미지를 만들고… 진행 상황이 이렇게 실시간으로 올라옵니다.

실제 영상 생성은 이미지 열몇 장에 음성 더빙, 영상 합성까지라 몇 분 걸려요. 그래서 **미리 돌려둔 결과물**을 보여드릴게요.

[화면] 미리 렌더한 최종 쇼츠 MP4 재생. 세로 9:16, 제목 + 장면 자막 + 더빙 + 배경음.

이렇게 **1분짜리 세로 쇼츠가 통째로 나옵니다.** 영상 제목, 장면마다 들어가는 큰 자막, 더빙 목소리, 배경음악까지 전부 자동으로 만들어진 거예요.

그리고 이게 쇼츠만 되는 게 아니에요. 똑같은 방식으로 **블로그 글이나 이미지, 긴 롱폼 영상**도, 말로 시키면 AI가 그에 맞는 워크플로우를 짜서 결과물까지 뽑아 줍니다.

정리하면, **'무엇을 원하는지'는 AI가 이해해서 워크플로우를 구성하고, '어떻게 안정적으로 만들지'는 검증된 자동화 흐름이 보장하는** 구조예요. 저희가 만든 Eureka Flow였습니다. 감사합니다.

## 예상 질문 & 답변

_방문자가 물으면 발표자가 답하는 부분. 과장하지 말 것 — 정직한 답이 오히려 설계를 안다는 인상을 준다._

**Q. AI가 매번 노드를 자유롭게 새로 고르는 건가요?**
정직하게 말씀드리면, 핵심 흐름인 쇼츠·롱폼·글·이미지는 **검증된 레시피(템플릿)** 를 씁니다. AI가 하는 판단은 '이 요청이 어떤 레시피에 맞는지'를 고르고 각 단계 내용을 채우는 거예요. 왜 그렇게 했냐면, 영상 생성은 비용도 들고 품질이 일정해야 하거든요. 매번 AI가 그래프를 새로 짜면 유료 단계 전 검수 같은 안전장치를 빼먹거나 품질이 들쭉날쭉해져요. 그래서 **의도 판단·구성·내용 생성은 AI가 맡고, 구조와 순서, 비용·안전 게이트는 코드로 고정**했습니다. 대신 어떤 레시피에도 안 맞는 요청은 AI가 블록을 직접 조립하는 경로도 있어요.

**Q. n8n이나 Zapier랑 뭐가 다른가요?**
그런 도구들은 사람이 노드를 직접 연결해야 해요. 저흰 자연어로 시키면 AI가 워크플로우를 자동으로 구성합니다. 그리고 백엔드가 서버리스라 실행이 이벤트 기반으로 붙고, 진행 상황을 실시간으로 보여줘요. 한 줄로 'n8n에 AI 오케스트레이터와 서버리스를 더한 것'이라고 보시면 됩니다.

**Q. 기술적으로 제일 어려웠던 부분은?**
두 가지였어요. 하나는 자연어 요청을 잘못 분류하지 않게 만드는 의도 판단이고요. 다른 하나는 영상처럼 돈 드는 단계 전에 멈춰서 사람이 검수한 다음, 처음부터 다시 안 돌리고 **그 지점부터 이어서 실행**하는 흐름이에요. 이 중간 체크포인트에서 재개하는 구조를 직접 설계한 게 제일 까다로웠습니다.

**Q. 모델은 뭘 쓰나요?**
오케스트레이션이랑 대본, 이미지는 OpenAI 계열을 씁니다. 음성 더빙은 **ElevenLabs가 기본**이고요, ElevenLabs 키가 없을 때만 OpenAI 음성으로 폴백하게 돼 있어요. 프로바이더는 전부 어댑터로 분리해서 교체할 수 있게 해뒀습니다.

**Q. 실제로 돌아가는 건가요, 목업인가요?**
실제로 돌아갑니다. 방금 노드 실행되는 건 실시간이고, 영상도 실제 생성물이에요. 부스에선 시간이랑 비용 때문에 미리 만들어둔 걸 재생하는 것뿐입니다.

### 개발자용 기술 질문

_개발자나 교수님이 깊게 물을 때. 답변은 실제 구조 그대로다._

**Q. 백엔드를 왜 서버리스(Lambda)로 했어요? Express 안 쓰고?**
실행이 이벤트 기반이고 노드 단위로 끊겨서요. 요청 들어올 때만 함수가 뜨고 부하 따라 자동으로 스케일되니까, 영상 안 만들 땐 비용이 거의 0이에요. 워크플로우 실행이라는 성격이랑 서버리스가 잘 맞았습니다. 로컬에선 serverless offline으로 똑같이 돌리고요.

**Q. 워크플로우 DAG는 어떻게 실행돼요? 노드 순서랑 병렬 처리는요?**
그래프를 위상정렬해서 '웨이브' 단위로 나눠요. 서로 의존 없는 노드는 같은 웨이브라 **병렬로 실행**합니다. 예를 들어 이미지 생성이랑 음성(TTS)은 대본이 나온 다음 동시에 돌아요. 노드 상태는 DynamoDB에 저장하고, 실행 큐는 SQS, 진행 상황은 WebSocket으로 프론트에 실시간 푸시합니다.

**Q. 노드가 중복 실행되거나 중간에 실패하면요? 멱등성이랑 재시도는?**
노드마다 상태머신이 있어요. PENDING → RUNNING → COMPLETED로 가고, **이미 끝난 노드는 다시 호출돼도 스킵**해서 멱등하게 만들었어요. 블록별로 재시도 횟수랑 타임아웃 예산이 따로 있고요. 한 노드가 실패하면 뒤쪽 PENDING 노드들은 SKIPPED 처리하고 run을 FAILED로 끝냅니다.

**Q. LLM이 JSON을 깨서 주면 어떻게 처리해요? (앞뒤에 설명 붙이거나 잘리거나)**
그게 실제로 자주 나는 문제라 파서를 따로 만들었어요. 앞뒤 설명문(prose)을 벗기고, 코드펜스로 감싼 것도 풀고, 본문에서 첫 번째 JSON 객체만 추출하고, **꼬리가 살짝 잘린 경우엔 열린 괄호·따옴표를 닫아서 복구**합니다. 그래도 안 되면 안전한 fallback 응답으로 떨어지고요.

**Q. 영상·이미지는 돈이 드는데 비용 폭주는 어떻게 막아요?**
세 겹이에요. 실행 전에 비용 한도를 체크하고, **유료 단계(이미지·영상) 전에 멈춰서 사람이 검수하는 게이트**가 있고, 유료 OpenAI 호출은 명시적 플래그가 켜져 있어야만 나갑니다. 핵심은 AI가 비싼 노드를 멋대로 끼워넣지 못하게 **구조(레시피)로 막은** 거예요.

**Q. 앵글 선택처럼 중간에 멈췄다가 처음부터 다시 안 돌리고 이어서 실행하는 건 어떻게 했어요?**
재개 지점 노드를 기준으로, **그 노드랑 하위 노드만 실행 스냅샷에 넣어요.** 재개 노드는 '완료' 상태로 선택값까지 채워서 seed하고, 그 다음 노드부터 PENDING으로 시작하죠. 그래서 트렌드 수집이나 브리프 같은 상류 노드는 아예 스냅샷에서 빠져서 다시 안 돕니다. 단일 블록 실행이랑은 다른, downstream만 이어가는 흐름이에요.

**Q. 오케스트레이터가 LLM이라 비결정적인데 테스트는 어떻게 해요?**
mock 오케스트레이터 모드를 둬서 LLM 없이 결정적으로 테스트해요. 실제 LLM 응답은 zod 스키마로 검증하고, 스키마에 안 맞으면 fallback으로 떨어집니다. 그리고 돈 드는 경로는 테스트에서 기본적으로 막혀 있어서 실수로 과금될 일이 없게 했어요.

**Q. 프론트랑 백엔드 타입은 어떻게 맞춰요?**
공유 패키지(libs/contracts)에 zod 스키마를 한 군데 정의하고 양쪽이 같이 씁니다. 노드·엣지·run 요청/응답이 전부 거기서 나와서, 스키마 바꾸면 양쪽 타입이 같이 따라와요. 모노레포(Nx)라 가능한 구조고요.

**Q. 프로바이더(OpenAI / ElevenLabs 등)는 어떻게 갈아끼워요?**
각 외부 서비스를 어댑터로 감싸뒀어요. 예를 들어 음성은 ElevenLabs 키가 있으면 그쪽, 없으면 OpenAI로 폴백하는 식이라, 블록 코드는 안 건드리고 어댑터/키만 바꾸면 프로바이더가 교체됩니다.
